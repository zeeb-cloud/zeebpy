From the Database to the Web

Serializers, viewsets, and routers — the airport that moves a web request in and a tidy reply back out.

Those queries you wrote? Now the whole world can trigger them.

In the last module you ran queries inside your own program. But real apps get poked from the outside — someone opens a browser or a phone app and does something.

So: when someone visits HTTP request like POST /books/ to add a new book, how does that become a real row in your database — and a clean reply on the way back? Follow the request through the airport.

✈️
The metaphor: an airport

A request is a passenger with a ticket. Three staff members get it to the right place and back — you will meet them next.

Meet the three airport staff

Every web request is handled by the same three roles. Learn who does what, and debugging stops being guesswork.

🪧
The router — terminal signage

Reads the address on the ticket (/books/) and points the passenger to the correct gate.

🧑‍✈️
The viewset — the gate agent

Handles everything you can do to Books: create one, read one, update one, delete one.

🛂
The serializer — passport control

Inspects everything coming in (is this valid?) and shapes everything going out (into clean JSON).

Why this matters

Each layer has one job. When something breaks, the layer tells you where to look — no more staring at the whole app at once.

Passport control, in code

Here is a real serializer. It declares exactly which fields are allowed through the gate — nothing else gets in or out.

CODE 
class BookSerializer(ModelSerializer):
    """Serializer for Book model."""
    author_name = SerializerMethodField()

    class Meta:
        model = Book
        fields = ["id", "title", "author_id", "author_name", "published_year",
                  "genre", "price", "in_stock"]
        read_only_fields = ["id"]

Define how a Book is checked and shaped as it enters or leaves the web.

The gate agent, in code

The viewset is almost embarrassingly short. You point it at some data and at a serializer — and full CRUD comes free.

CODE 
class BookViewSet(ModelViewSet):
    """
    ViewSet for Book CRUD operations.

    Query with Q filters via POST /books/query/
    """
    queryset = Book.objects
    serializer_class = BookSerializer
PLAIN ENGLISH

Define the handler for everything you can do to Books over the web.

A description of this handler...

It provides full create / read / update / delete out of the box...

 

...plus a bonus query endpoint for advanced filtering.

(end of the description)

Point it at the Book data — which set of rows it manages.

Tell it which serializer to use for checking and shaping data. That is all — the CRUD web addresses come for free.

The signage that wires it all up

The router connects addresses to handlers. Two lines here create dozens of working web addresses.

CODE 
router = DefaultRouter()
router.register("authors", AuthorViewSet, basename="author")
router.register("books", BookViewSet, basename="book")
PLAIN ENGLISH

Create a router — the thing that maps web addresses to handlers.

Register the Author handler under the /authors/ addresses.

Register the Book handler under the /books/ addresses. From these two lines, zeebpy generates GET / POST / PUT / PATCH / DELETE routes automatically.

🚪
One definition, many endpoints

From a serializer + a viewset + one register() line, zeebpy generates a whole family of endpoints. That is the payoff of a framework — you describe the shape, it builds the doors.

The doors you just built for free

That single register("books", ...) line opened all of these — no extra code:

GET /books/ List every book
POST /books/ Create a new book
GET /books/{id}/ Read one book by its id
PUT /books/{id}/ Replace a book fully
PATCH /books/{id}/ Update just a few fields
DELETE /books/{id}/ Remove a book

The error tells you which layer to blame

Because each layer has one job, the status code points straight at the culprit. This is your debugging cheat sheet.

🛂

422 Unprocessable

The serializer rejected your data. Validation failed — a missing or wrong-typed field. Look at the serializer.

🪧

404 Not Found

The router did not recognize the address (or the id does not exist). Check the route and the URL you called.

✅

201 Created

Everything worked and a new row was saved. The reply carries the fresh item as JSON.
